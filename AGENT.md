# AGENT.md — ScreenRec (кроссплатформенное приложение записи экрана)

Этот файл описывает проект для AI-агента (Claude Code / другого ассистента-разработчика).
Здесь фиксируются архитектура, требования, команды сборки/очистки и функциональные спецификации.
Агент должен придерживаться этого документа при генерации кода, структуры проекта и скриптов.

---

## 1. Общее описание проекта

Кроссплатформенное десктопное приложение для записи экрана (Windows / Linux).

Ключевые возможности:
- запись всего экрана;
- запись выбранной области экрана;
- запись выбранного окна приложения;
- запись выбранной вкладки браузера;
- запись продолжается, даже если само приложение и/или записываемое окно/вкладка свёрнуты;
- работа из системного трея (сворачивание при закрытии, полноценный выход — отдельным пунктом);
- автозапуск вместе с системой (Windows/Linux);
- каталогизатор записей с указанием пути хранения и встроенным плеером предпросмотра;
- наложение водяного знака (картинка и/или текст) с шаблонизатором позиционирования;
- несколько цветовых тем интерфейса, синхронизированных со стилем иконки приложения.

Проект должен разрабатываться и запускаться **только внутри виртуального окружения Python** (venv).

---

## 2. Технологический стек (рекомендация для агента)

- **Язык:** Python 3.11+
- **GUI:** PySide6 (Qt for Python) — даёт нормальную поддержку трея, оверлеев для выбора области/окна, кроссплатформенность.
- **Запись экрана / захват:**
  - Windows: `mss` для кадров + `ffmpeg` (через subprocess) для кодирования; либо захват через `dxcam`/`Windows Graphics Capture API` при необходимости высокой производительности.
  - Linux: `mss` + `ffmpeg` (X11 через `x11grab`, Wayland — через `wf-recorder`/`pipewire`, отдельная ветка логики).
- **Аудио (опционально, если потребуется):** `sounddevice` + смешивание через ffmpeg.
- **Автозапуск:**
  - Windows: запись в `HKCU\Software\Microsoft\Windows\CurrentVersion\Run` или ярлык в `shell:startup`.
  - Linux: `.desktop`-файл в `~/.config/autostart/`.
- **Трей:** `QSystemTrayIcon` (PySide6).
- **Хранение настроек/шаблонов:** JSON или SQLite в пользовательской конфиг-директории (`platformdirs`).
- **Упаковка в исполняемый файл:** `PyInstaller` (отдельные конфиги/спеки для Windows и Linux).

Агент может предложить альтернативы, но должен явно обосновать отклонение от указанного стека.

## 4. Виртуальное окружение

Все зависимости, запуск и сборка выполняются строго внутри venv.

**Создание окружения (Windows, `scripts/setup_venv_windows.bat`):**
```bat
@echo off
python -m venv .venv
call .venv\Scripts\activate.bat
pip install --upgrade pip
pip install -r requirements.txt
echo Virtual environment ready.
```

**Создание окружения (Linux, `scripts/setup_venv_linux.sh`):**
```bash
#!/usr/bin/env bash
set -e
python3 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt
echo "Virtual environment ready."
```

Агент обязан:
- проверять активацию venv перед установкой пакетов или запуском сборки;
- не устанавливать зависимости глобально;
- при добавлении новой библиотеки — обновлять `requirements.txt`.

## 5. Скрипты сборки

**Windows (`scripts/build_windows.bat`):**
```bat
@echo off
call .venv\Scripts\activate.bat
pyinstaller --noconfirm --windowed --onefile ^
  --name ScreenRec ^
  --icon src\screenrec\assets\icons\icon_blue.ico ^
  --add-data "src\screenrec\assets;screenrec\assets" ^
  --add-data "src\screenrec\ui\themes;screenrec\ui\themes" ^
  src\screenrec\main.py
echo Build finished. See dist\ScreenRec.exe
```

**Linux (`scripts/build_linux.sh`):**
```bash
#!/usr/bin/env bash
set -e
source .venv/bin/activate
pyinstaller --noconfirm --windowed --onefile \
  --name screenrec \
  --icon src/screenrec/assets/icons/icon_blue.png \
  --add-data "src/screenrec/assets:screenrec/assets" \
  --add-data "src/screenrec/ui/themes:screenrec/ui/themes" \
  src/screenrec/main.py
echo "Build finished. See dist/screenrec"
```

Требования к скрипту сборки:
- собирать в один исполняемый файл (`--onefile`) без консольного окна (`--windowed`);
- включать иконки всех тем и qss-файлы тем как ресурсы;
- итоговый бинарник должен запускаться без установленного Python/venv на целевой машине.

## 7. Иконка и стиль приложения

- Иконка приложения — комбинация **монитора и видеокамеры** (символ записи экрана).
- Доступны 4 цветовых варианта иконки: **зелёный, синий, серый, чёрный**.
- Каждому варианту иконки соответствует одноимённая тема оформления интерфейса (qss/palette): зелёная, синяя, серая, чёрная.
- Смена темы в меню настроек автоматически меняет:
  - палитру интерфейса (акценты, фон, кнопки);
  - иконку в трее и в заголовке окна на соответствующий цветовой вариант.
- `theme_manager.py` должен хранить единый маппинг `theme_name -> {qss_path, tray_icon_path, window_icon_path}` — не разносить логику темы и иконки по разным местам.

## 8. Функциональность записи

### 8.1 Режимы записи
- **Весь экран** — захват основного/выбранного монитора (поддержка мультимониторной конфигурации).
- **Область экрана** — оверлей с перетаскиваемым/растягиваемым прямоугольником выбора, сохранение последней выбранной области.
- **Окно приложения** — выбор из списка активных окон (по хендлу/PID), захват именно этого окна даже при перекрытии другими окнами.
- **Вкладка браузера** — выбор конкретной вкладки (через выбор окна браузера +, если технически возможно, привязку к активной вкладке; для MVP допустимо реализовать как захват окна браузера с фиксацией на активной вкладке в момент старта записи).

### 8.2 Запись в свёрнутом состоянии
- Запись должна продолжаться, если:
  - главное окно ScreenRec свёрнуто в трей;
  - записываемое окно/вкладка свёрнуто или неактивно (не в фокусе).
- Технически это означает: захват должен идти по хендлу/ID окна или по буферу экрана независимо от фокуса и видимости (там, где ОС это позволяет — на Windows это возможно через PrintWindow/BitBlt с флагами для свёрнутых окон, на Linux зависит от X11/Wayland — необходимо явно обработать оба случая и задокументировать ограничения Wayland).

### 8.3 Включаемые/отключаемые функции (через меню настроек)
Каждая функция — независимый переключатель (toggle) в меню:
- запись звука с микрофона (вкл/выкл);
- запись системного звука (вкл/выкл);
- показ курсора мыши в записи (вкл/выкл);
- запись в свёрнутом виде (вкл/выкл);
- автозапуск с системой (вкл/выкл);
- сворачивание в трей при закрытии (вкл/выкл) — если выключено, закрытие крестиком равно полноценному выходу;
- наложение водяного знака/текста (вкл/выкл);
- уведомления (старт/стоп записи, ошибки) (вкл/выкл).

## 9. Системный трей

### 9.1 Поведение при закрытии окна
- Клик по крестику окна → сворачивание в трей (если включена соответствующая настройка), процесс продолжает работать.
- В главном меню приложения должен быть отдельный явный пункт **«Закрыть» / «Выход»**, который завершает процесс полностью (не сворачивает).

### 9.2 Контекстное меню иконки в трее (правая кнопка мыши)
Обязательные пункты:
- **Начать запись** / **Остановить запись** (один переключаемый пункт или два раздельных, но состояние должно чётко отражать текущий статус — например, через смену иконки/чекбокс);
- Открыть главное окно;
- Быстрый выбор режима записи (весь экран / область / окно / вкладка) — опционально как подменю;
- **Выход** — полноценное закрытие приложения (останавливает запись, если она идёт, с подтверждением).

Двойной клик по иконке трея — открыть главное окно.

## 10. Автозапуск с системой

- Настройка «Запускать при старте системы» доступна в меню настроек.
- Windows: реализация через реестр (`Run`) или ярлык в папке автозагрузки; приложение при автозапуске стартует сразу свёрнутым в трей.
- Linux: реализация через `.desktop`-файл в `~/.config/autostart/` с параметром `X-GNOME-Autostart-enabled=true`; поддержка основных DE (GNOME/KDE/XFCE).
- Модули `autostart/windows.py` и `autostart/linux.py` должны иметь одинаковый интерфейс (`enable()`, `disable()`, `is_enabled()`), выбираемый в рантайме по `platform.system()`.

## 11. Каталогизатор записей

- Список всех записанных файлов (миниатюра/иконка, имя, дата, длительность, разрешение, размер).
- Настройка пути хранения записей (выбор папки), с возможностью сменить путь в любой момент (старые записи не переносятся автоматически, только новые пишутся в новый путь).
- Сортировка/фильтрация по дате и типу записи (экран/область/окно/вкладка).
- Встроенный плеер: выбор записи в каталоге → сразу воспроизведение внутри приложения (без внешнего плеера), с базовыми контролами (play/pause, перемотка, громкость, полноэкранный режим).
- Действия по записи: открыть в системном проводнике/файловом менеджере, удалить, переименовать, экспортировать/скопировать.

## 12. Водяной знак (картинка/текст) и шаблонизатор

### 12.1 Требования
- Возможность наложить на запись:
  - изображение (лого/картинка);
  - текст (произвольная строка, например для маркировки/подписи записи);
  - оба элемента одновременно.
- Редактор шаблона (`overlay_editor.py`):
  - превью кадра (снимок экрана или заглушка) как фон для позиционирования;
  - картинка и текстовый блок — отдельные перетаскиваемые и масштабируемые прямоугольники поверх превью;
  - настройка текста: содержимое, шрифт, размер, цвет, прозрачность;
  - настройка картинки: путь к файлу, масштаб, прозрачность;
  - сохранение положения/размера/параметров как **именованный шаблон**.
- При старте записи пользователь выбирает шаблон (или «без наложения»); выбранные элементы вставляются в кадр в заданных координатах на протяжении всей записи.
- Хранение шаблонов — в `config/templates.py`, формат JSON, координаты — в относительных величинах (0.0–1.0 от ширины/высоты кадра), чтобы шаблон корректно масштабировался при разных разрешениях записи.

### 12.2 Техническая реализация наложения
- Наложение выполняется на этапе кодирования (через фильтры ffmpeg `overlay`/`drawtext`) либо программно покадрово перед энкодером — агент выбирает подход исходя из производительности, но должен обеспечить синхронизацию положения с сохранённым шаблоном.

## 13. Логирование

### 13.1 Общие требования
- В проект обязательно включается модуль логирования (`src/screenrec/logger/logger.py`), построенный на стандартном `logging`.
- **По умолчанию логирование выключено.** Включается/выключается через настройки (см. 13.3).
- **Путь к лог-файлу по умолчанию** — тот же каталог, где расположен исполняемый файл/точка запуска программы (рядом с `.exe` на Windows или рядом с бинарником/`main.py` на Linux), файл вида `screenrec.log`.
  - Определение каталога запуска: для собранного `PyInstaller`-бинарника — через `sys.executable`/`os.path.dirname(sys.executable)`; для запуска из исходников — через каталог точки входа. Логика должна быть единой функцией `get_default_log_path()`, чтобы не дублировалась в разных модулях.
- Путь к лог-файлу должен быть **настраиваемым** — пользователь может указать другой каталог/файл через настройки; если путь недоступен для записи (нет прав, не существует) — приложение откатывается на путь по умолчанию и пишет об этом предупреждение в консоль/уведомление.
- Ротация лог-файла обязательна (например, `RotatingFileHandler`: ограничение по размеру, N резервных копий), чтобы лог не рос бесконечно при длительной работе.

### 13.2 Уровни логирования
Модуль должен поддерживать полный набор уровней (с маппингом на стандартный `logging`, где это возможно, и с добавлением недостающих кастомных уровней):

| Уровень (RU)     | Соответствие                                   |
|------------------|-------------------------------------------------|
| TRACE            | кастомный уровень ниже DEBUG (номер 5)          |
| DEBUG            | `logging.DEBUG`                                 |
| INFO             | `logging.INFO`                                  |
| WARNING          | `logging.WARNING`                               |
| ERROR            | `logging.ERROR`                                 |
| CRITICAL         | `logging.CRITICAL`                              |
| FATAL ERROR      | кастомный уровень выше CRITICAL (номер 60), приводит к контролируемому завершению работы модуля/приложения после записи в лог |

- `TRACE` регистрируется через `logging.addLevelName(5, "TRACE")` + метод-обёртка `logger.trace(...)`.
- `FATAL ERROR` регистрируется через `logging.addLevelName(60, "FATAL")` + метод-обёртка `logger.fatal_error(...)`; такие события всегда пишутся в лог независимо от установленного минимального уровня и, как правило, сопровождаются graceful shutdown.
- Минимальный уровень логирования (какие сообщения писать в файл) выбирается пользователем в настройках.

### 13.3 Настройка через меню
В меню «Настройки» → «Логирование» должны быть:
- переключатель **«Включить логирование»** [вкл/выкл] — по умолчанию выкл;
- выбор **пути к лог-файлу** (диалог выбора файла/папки), по умолчанию — каталог запуска программы;
- выбор **минимального уровня логирования** (TRACE / DEBUG / INFO / WARNING / ERROR / CRITICAL / FATAL) — по умолчанию INFO (применяется только если логирование включено);
- кнопка **«Открыть лог-файл»** / **«Открыть папку с логом»** для быстрого доступа;
- опционально: кнопка «Очистить лог».

### 13.4 Технические требования
- Формат строки лога должен включать: дату/время, уровень, модуль/источник, сообщение — например: `2026-09-13 10:00:00 | INFO | recorder.screen | Запись начата`.
- Логирование не должно быть завязано на конкретный модуль записи — это общий сквозной сервис, доступный из любой части приложения (`get_logger(__name__)`).
- Включение/выключение логирования и смена уровня в рантайме должны применяться без перезапуска приложения.
- Логирование должно фиксировать как минимум: старт/остановку записи, смену режима записи, ошибки захвата/кодирования, изменения настроек, события автозапуска, ошибки наложения водяного знака.

## 15. Требования к качеству и кроссплатформенности

- Весь платформозависимый код (захват экрана, автозапуск, работа с окнами) должен быть изолирован в отдельных модулях с единым интерфейсом и веткой выбора реализации по `platform.system()`.
- Не допускается захардкоженных путей вида `C:\...` или `/home/user/...` — использовать `platformdirs`/`pathlib`.
- Приложение должно корректно завершать процесс ffmpeg/запись при аварийном закрытии (обработка сигналов/исключений), чтобы не оставались битые файлы или зависшие процессы.
- Все скрипты (`scripts/*.bat`, `scripts/*.sh`) должны быть идемпотентными — повторный запуск не должен ломать проект.

## 17. История реализации 0.2.0 (2026-09-13)

- Этап 1 реализован: запись выбранного монитора, управление из окна/трея, выход с завершением FFmpeg.
- Структура `src/screenrec` сохранена; добавлен `recorder/worker.py` для фонового захвата в QThread.
- FFmpeg поставляется через `imageio-ffmpeg`, чтобы не требовать глобальной установки кодировщика.
- MP4 использует фрагменты для повышения устойчивости к аварийному завершению.
- Добавлены создание venv и запуск для Windows/Linux; установка проекта — `pip install -e .` внутри venv.
- Настройки папки, FPS, трея и уведомлений сохраняются в JSON через `platformdirs`.
- Windows проверен реальной записью; Linux X11 требует проверки на Linux. Wayland на этапе 1 явно отклоняется.
- Поддержка свёрнутых сторонних окон не реализована; PrintWindow/BitBlt не дают универсальной гарантии такого захвата. Для этапа 2 требуется проверка возможностей конкретного backend/приложения.
- Добавлен конфигуратор `ui/settings_dialog.py`: MP4/MKV/WebM, три уровня качества, FPS, четыре режима звука, устройства и аудиобитрейт. Единые профили — `config/recording.py`.
- Windows-звук изолирован в `recorder/audio_windows.py`: PyAudioWPatch/WASAPI, собственные частоты и каналы устройств. Linux использует SoundCard/PulseAudio через `recorder/audio.py`. Выбор библиотек обусловлен поддержкой loopback и устройств с различными форматами.
- `recorder/audio.py` запускает отдельный процесс для каждого аудиоисточника; зависшие устройства завершаются по тайм-ауту. Режим «Без звука» не запускает аудиозахват.
- `recorder/muxer.py` добавляет и смешивает WAV после остановки, без повторного кодирования видео. Промежуточная папка `.ScreenRec_….parts` удаляется только после успеха; при ошибке сохраняется для восстановления.
- Обязательная сборка одного EXE реализована: `scripts/build_windows.bat` → `scripts/build.py` → `dist/ScreenRec.exe`; включены Qt, FFmpeg, аудиозахват и ресурсы. `scripts/launcher.py` обеспечивает корректный запуск упакованного приложения и аудиопроцессов.
- `--self-test` — явный диагностический режим для проверки записи и ресурсов из EXE, с JSON-отчётом и автоматическим выходом. Обычный запуск не начинает запись.
- Проверены 9 автотестов, все 9 сочетаний формата/качества, реальная запись экрана с обоими источниками звука. Остальные функции исходного плана ещё не реализованы. Подробности — в README.md.
- Сборщик ограничивает PATH системным каталогом Windows и venv, чтобы чужие DLL (например, ICU из другой программы) не попадали в EXE; совместимые VC Runtime включаются явно. Автономная проверка — `scripts/smoke_exe.ps1`.
- Готовый EXE проверен из отдельной папки без Python в PATH: MP4 с реальным экраном и двумя аудиоисточниками, MP4 без звука, MKV с микрофоном, WebM с системным звуком. Подтверждены декодирование, использование встроенного FFmpeg и завершение дочерних процессов; размер EXE около 90 МБ.

## 19. Источники записи и запрет публикации (релиз 0.3.0)

По требованию пользователя реализовать выбор монитора, области мышью, конкретного окна и конкретной вкладки браузера.
Вкладка Chrome/Edge захватывается локальным расширением Manifest V3, привязывающим запись к выбранной вкладке через tabCapture; автоматическая установка расширения не производится.
Windows: Windows Graphics Capture по HWND; Linux X11: XComposite при наличии поддержки. Нельзя подменять захват окна вырезкой монитора при перекрытии. Ограничения сворачивания и защищённого контента показывать явно.
Передавать данные вкладки только на loopback, с отдельным случайным токеном сеанса. Настройки формата, качества и звука сохраняются для всех источников.
**Никогда не публиковать код, коммиты, теги, релизы или расширение в GitHub/магазинах/внешних сервисах без отдельной прямой команды пользователя. Все действия текущего проекта локальные.**

Состояние 0.3.0: реализованы выбор источника, область мышью с учётом DPI, список окон, WindowsCapture по HWND, XComposite и локальное расширение Chrome/Edge. Расширение встроено в EXE, экспортируется пользователем и включено в ZIP релиза. Системный звук общий для устройства, изоляции звука вкладки нет. Свёрнутые окна не гарантируются, Linux требует проверки. Добавлены автотесты протокола и области, scripts/smoke_sources.py и scripts/smoke_browser.py.
