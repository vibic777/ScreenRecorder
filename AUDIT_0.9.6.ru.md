# Проверка надёжности ScreenRec 0.9.6 — 2026-09-30

Проверены жизненный цикл записи, FFmpeg, аудиопроцессы, браузерный протокол и расширение, настройки и профили, захват экрана/окна, предпросмотр, блокировка экземпляров и упаковка. Исправления общие для Modern и Legacy, кроме явно указанных платформенных участков.

## Найдено и исправлено

| Приоритет | Ошибка | Исправление |
| --- | --- | --- |
| Критический | После ошибки объединения звука и видео удалялись пригодные для восстановления дорожки | После начала записи `.parts` сохраняется при ошибках. Очистка неудачного старта остаётся, но только для созданной этим сеансом папки |
| Высокий | Зависший FFmpeg мог навсегда заблокировать запись в stdin, до вызова finish | Один watchdog на энкодер ограничивает каждую запись 15 секундами и завершает зависший процесс; тест использует настоящий дочерний процесс, не читающий pipe |
| Высокий | Кадр неверного размера нарушал границы rawvideo | Размер BGRA проверяется до записи; короткие записи в pipe дописываются |
| Высокий | Импорт профиля обходил проверку вложенных значений, включая уровни логирования | Общая нормализация с Settings.load; огромные целые координаты/размеры не вызывают OverflowError |
| Высокий | Импорт профиля оставлял старую папку/источник в UI и был доступен во время записи | Синхронизация UI и каталога; импорт блокируется на время сеанса |
| Высокий | Linux-ветка блокировки экземпляра обращалась к недоступному Settings и не создавала каталог; Windows CloseHandle не имел 64-битной сигнатуры | Исправлены импорт, создание каталога и ctypes-сигнатура |
| Средний | Одновременные сохранения использовали общий settings.tmp; экспорт профиля мог обрезать старый файл | Уникальные временные файлы, flush/fsync и атомарная замена для настроек, профилей и шаблонов |
| Средний | `/begin` и `/abort` с JSON-массивом обрывали обработчик; размер чанка мог меняться; `/end` принимал недописанный чанк | Проверка объекта, постоянного размера и завершённости чанка; ошибочный запрос не завершает сеанс |
| Средний | Отмена подключения вкладки оставляла скрытые временные файлы; ошибка закрытия могла помешать сообщению об ошибке | Очистка пустого сеанса и обработка исключений при закрытии; непустая запись сохраняется |
| Средний | Двойной запуск расширения во время getUserMedia мог перезаписать состояние активного сеанса | Блокировка состояния до первого await, сброс после ошибки, обработка отмены старта |
| Средний | Ошибка удаления временных файлов превращала успешно сохранённую запись в неуспешную | Ошибка очистки логируется отдельно от результата записи |
| Средний | Отключение логирования и выбор уровней терялись при перезапуске | Удалено принудительное включение всех уровней при каждом старте |
| Ресурсы | Полная копия кадра экрана, дополнительные копии кадра окна, дисковый лог на каждом кадре | Используются уже принадлежащий снимку raw-буфер и memoryview; окно копируется один раз для владения памятью; покадровый лог удалён |
| Ресурсы | Быстрое переключение Legacy-предпросмотра накапливало декодирование устаревших файлов | Отмена ожидающих запросов, игнорирование старых результатов, закрытие executor при shutdown |
| Ресурсы | Аудиосеансы сохраняли дескрипторы завершённых Process; неудачная подготовка overlay оставляла PNG | Явное закрытие Process/Queue и очистка неудачной подготовки |
| Средний | Legacy мог продолжать вырезать рабочий стол по координатам свёрнутого окна | Явная ошибка до захвата; автоматическая подмена источника не выполняется |
| Релиз | ZIP расширения терял вложенные `_locales`, пакет также не объявлял их; релизный скрипт собирал только Modern | Рекурсивная упаковка локалей, обе сборки из одного чистого коммита, отдельные lock-файлы, EXE/ZIP, manifest и SHA-256 |

## Проверки

- Modern: unittest, compileall, pip check. Регрессионные тесты проверяют сохранность дорожек, зависший pipe, повреждённые профили, атомарную запись, UI, браузерный протокол и ресурсы предпросмотра.
- Legacy: Python 3.8 compileall и импорт приложения/записи/профилей, pip check.
- JavaScript: `node --check` для трёх файлов расширения; `node tests/test_extension.js` проверяет двойной старт и восстановление после ошибки.
- Настоящий tabCapture проверен локальным Chromium: переключение на другую вкладку не меняет записываемый источник. Использован имеющийся Chromium через `SCREENREC_TEST_CHROMIUM`; новые браузеры не устанавливались.
- Релизный скрипт допускает готовый `releases/0.9.6` только после автономных self-test обоих EXE: синтетический источник и настоящее окно, декодирование результата, наложения, логирование и плеер. Результаты записываются в manifest.json, полные отчёты — в `.test-output/release-0.9.6-*`.

## Границы проверки и ручная приёмка

Windows 8/8.1 и Linux в этой среде недоступны: проверка веток/импортов не заменяет запуск на этих ОС. Длительные многочасовые записи и все сочетания устройств/драйверов не проверены. Сокращение копирований подтверждено кодом и тестами; универсального прироста FPS или снижения CPU в процентах не заявляется.

Для приёмки проверьте обе подходящие вашей ОС сборки: экран и окно, остановку/повторный старт, выбранные аудиоустройства, наложения, воспроизведение, импорт профиля и сохранение отключённого логирования после перезапуска. На Windows 8.1 особенно проверьте звук и плеер. Legacy захватывает прямоугольник рабочего стола: перекрывающее окно попадёт в запись. Modern не гарантирует запись свёрнутых/защищённых окон.

При ошибке объединения не удаляйте указанную в сообщении папку `.parts`: там остаются исходные видео и WAV. Публикация и push выполняются только по отдельной команде пользователя.
